# 安全与开源边界

本项目处理的是 **车主自己的官方云会话** 和 **车辆状态**。默认按「自托管、最小泄露」设计。

## 凭证

| 秘密 | 位置 | 规则 |
|---|---|---|
| 官方 `refresh_token` / `access_token` | 仅服务端，加密列 | 永不进入 owner/admin 前端、日志、错误回显、HAR 提交 |
| 本服务 `FENGHUOLUN_TOKEN_KEK` | 环境变量 | 丢失等于无法解密旧凭证，需车主重新绑定；不要提交 `.env` |
| 车主会话 | 客户端安全存储 + 服务端哈希 | 与官方 token 不是同一种东西 |
| 管理员密码 | 哈希 | 独立体系 |
| 官方 appKey / 证书 / 私钥 | 若第 1 期证明需要 | 本机文件路径，不进 git |

加密：AES-256-GCM 或等价 AEAD，KEK 来自环境。禁止仅 Base64。

## 归属

`owner` 的每一读、每一同步：会话 → `bindingId` → VIN。禁止请求体带任意 VIN 就去上游查。管理员也不能用后台触发「对官方的写车辆命令」（本期无此命令）。

## 日志与 VIN

- 日志用 `bindingId` + `vinMasked`（例如 `****1234`）
- 禁止打印 Authorization、Cookie、表单里的 token
- 上游响应只在 debug 且本地环境记录，默认关

## HAR 与抓包

- 根 `.gitignore` 已忽略 `*.har`
- `1.har` 含手机号、VIN、坐标、token、验证码、设备 id、数字钥匙、MQTT。**不得**复制进 `docs/`、`testdata/`、Issue、聊天归档
- 分析结论写在本机 `HAR-ANALYSIS.md`（不进仓库）和 `09-protocol-neta.md`，只留结构与非个人示例值
- 若该 HAR 曾离开本机，视为会话可能泄露，应在官方侧失效 token（由车主在官方 App 处理），本仓库不负责任意传播

## 开源发布检查单

发布或 push 前：

- [x] 无 `*.har`、无 `.env`、无真实 token
- [x] testdata 中 VIN 为明显假值（如 `TESTVIN0000000001`）
- [x] 文档不含手机号、真实坐标、真实里程与上报时间戳
- [x] 客户端证书、私钥不在树内

## 威胁模型（一期）

关心：

- 绑定接口被刷导致把攻击者 token 写入（可加基础限流；仍是攻击者自己的车）
- 会话被盗 → 能看该车况（HTTPS、会话过期、安全存储）
- 管理员会话被盗 → 能看脱敏运维数据
- 管理员会话被盗且容器挂了 `docker.sock` → 能重建本容器（后台一点更新）。sock 等于宿主机 Docker 权限；不需要此能力就不要挂
- 仓库误提交 HAR

不关心（明确不做）：把本服务做成对抗官方 PKI 的破解器、提取数字钥匙、打车机。
