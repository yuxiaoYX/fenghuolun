## 第 1 期 — 只读协议打通（核心风险期）

**目标：** 用真实 `refresh_token` 在服务端完成：换票 → 当前车辆 → 车况解码 → 官方能耗。前台可以先简陋，但数字必须诚实。

完成标准：

- [x] V1 换票：探活成功，脱敏写入 `09-protocol-neta.md`；`Client.Refresh` 只实现该路径
- [x] `getCurrentVehicle` 解析车型、VIN（脱敏展示）；EP32 识别为哪吒 L（解码单测用脱敏样例）
- [x] `getAppVehicleData` 解码层：未知保持 null；候选缩放集中写在 `internal/neta`，默认关，可用 `FENGHUOLUN_NETA_SCALE=candidate` 打开
- [x] 官方能耗独立模型（kWh 分项）；油耗走快照差分，不把 kWh 编成升
- [x] `fetchedAt` / `reportedAt` 都在 API 与「车况」出现
- [x] 换票失败：车主看到「请重新填写 refresh_token」，清会话回绑定页
- [x] 无车控、无短信登录、无浏览器直连

**本阶段允许：** 用临时 HTTP 工具或最小 owner 页提交 token 做联调。  
**本阶段禁止：** 宣称「已完整接入官方」、启用任何写车辆命令。

若 V1/V2（换票或签名）卡住：第 1 期标记为 **阻塞**，转入「可导入脱敏 JSON / 只展示历史」的降级，不得靠编造签名器过关。

## 第 2 期 — 落库与管理员

**目标：** 多车主绑定可运维，历史可查。

- [x] 车主会话与管理员会话分离（owner_session / admin_session 两表，中间件分开）
- [x] 手动同步 + 可选定时同步（空库读 `FENGHUOLUN_CRON_SYNC`，之后以后台 `app_settings` 为准并热替换；只换票并拉车况/能耗）
- [x] 管理员运维台（antdv-next）：登录、总览、绑定（停用/恢复/立即同步）、详情、任务历史、脱敏库表、运行时设置、改密/退出；看不到明文 token

- [x] owner 前台信息架构：车况 / 车控(占位) / 能耗 / 电池 / 我的（绑定与关于）。视觉对齐 `docs/wireframes/hifi-v2.html`
